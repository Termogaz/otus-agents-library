# AGENTS.md

## Проект и стек

Веб-приложение библиотеки: книги (с несколькими экземплярами), читатели, выдача и возврат,
лимит книг на читателя, сроки и просрочка. Fullstack TypeScript: Express 5 + zod на сервере,
React + Vite на клиенте, хранилище — JSON-файл за интерфейсом репозитория (позже SQLite).
Тесты: Vitest + supertest (unit/API), Playwright (e2e). Учебный проект курса OTUS «AI Agents»,
план и roadmap — в `docs/plan.md`.

## Конвенции

### Структура и слои

```text
src/domain/   бизнес-правила: чистые функции и типы, без I/O
src/server/   Express: маршруты, валидация входа (zod), хранилище
src/client/   React UI
tests/unit/   Vitest; tests/e2e/ — Playwright
```

- Зависимости направлены внутрь: `client` → (HTTP) → `server` → `domain`.
  `domain` не импортирует ничего из `server`, `client`, Express, React, `fs`.
- Бизнес-правило (лимит, срок, доступность экземпляра) живёт только в `domain`.
  Маршрут Express: разобрать вход → вызвать домен → сохранить → ответить.
- Хранилище доступно только через интерфейс репозитория; домен о файлах не знает.

### Стиль кода

- TypeScript strict, без `any`; внешний вход проверяется zod-схемой на границе `server`.
- Ожидаемые отказы домена (нет свободных экземпляров, превышен лимит) — типизированный
  результат или собственный класс ошибки с кодом, не строка. API отвечает `4xx` с этим кодом.
- Даты в домене передаются параметром (`now: Date`), не берутся из `new Date()` внутри
  правил — иначе их нельзя протестировать.
- Форматирование — только Prettier; стиль вручную не подгонять.

### Именование

- Файлы: `kebab-case.ts`; React-компоненты: `PascalCase.tsx`.
- Типы и классы — `PascalCase`, функции и переменные — `camelCase`.
- Тесты: `tests/unit/<модуль>.test.ts`; имена тестов на английском, описывают поведение:
  `it('rejects loan when reader reached the limit')`.
- Тексты интерфейса — на русском.
- Комментарии в коде — на русском.

## Правила работы

### Процесс

- Работа — в ветках `feat/<кратко>` или `fix/<кратко>`; в `main` только через Pull Request.
- Коммиты — Conventional Commits: `feat: ...`, `fix: ...`, `test: ...`, `docs: ...`, `chore: ...`.
  Тип — по-английски, описание и тело коммита — на русском: `docs: добавить rules для domain и e2e`.
  Заголовок и описание Pull Request — тоже на русском.
- Без атрибуции агента: никаких `Co-Authored-By: Claude ...` в коммитах и
  «Generated with Claude Code» в Pull Request.
- Бизнес-правила — через TDD: сначала падающий тест, затем минимальный код, затем рефакторинг.
- Задача готова, только когда `npm run check` зелёный, а для изменений UI — и `npm run test:e2e`.
- Крупную задачу делить на шаги, проверяемые по отдельности; отмечать прогресс в `docs/plan.md`.
- В конце сессии или шага — запись в `docs/memory.md`: сделано / решение / дальше / ловушки.
- Если инструкция противоречит другой или задачу нельзя выполнить по правилам — остановиться
  и спросить, а не выбирать молча.

### Агенту запрещено

- Читать, создавать или менять `.env*` и любые файлы с секретами.
- Добавлять или обновлять npm-зависимости без согласования; править `package-lock.json` вручную.
- Отключать проверки: `.skip`/`.only` в тестах, `eslint-disable`, `@ts-ignore`, ослаблять
  `tsconfig.json` или конфиг ESLint, чтобы «прошло».
- Удалять или переписывать тесты, чтобы они проходили, вместо исправления кода.
- Коммитить в `main`, делать `git push --force`, переписывать опубликованную историю.
- Менять формат сохранённых данных без миграции существующих.

## Ловушки окружения

- npm через локальный HTTP-прокси может падать с `ECONNRESET`. Решение — запускать npm
  с отключёнными переменными прокси: `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY npm ci`.
- `npm run test:e2e` с переменными прокси падает с `Timed out waiting 60000ms from config.webServer`:
  запускать так же через `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY`.
- Chromium для Playwright в WSL: один раз `npx playwright install chromium` и
  `sudo npx playwright install-deps chromium` (иначе `libnspr4.so: cannot open shared object file`).
- GSD Core требует Node ≥ 24 (через nvm). Сессия Claude Code, запущенная до установки
  nvm, видит системный Node 22 — для `/gsd-*` нужна новая сессия. Файлы GSD не в git:
  восстановить — `npx @opengsd/gsd-core@1.18.0 --claude --local`.
- Проект лежит в файловой системе WSL (`~/projects/library`), не на `/mnt/c`: там npm и
  hooks работают в разы быстрее.
