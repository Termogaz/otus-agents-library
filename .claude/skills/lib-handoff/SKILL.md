# Запись в docs/memory.md

Тема шага: `$ARGUMENTS` (если пусто — выведи из разговора и коммитов).

## 1. Собрать факты

- `git branch --show-current`, `git status --short`, `git log --oneline -10` — что закоммичено
  в этом шаге, что ещё нет.
- Прочитай начало `docs/memory.md`: формат, нумерацию шагов и последнюю запись (не повторяй её).
- Из разговора: что сделано, какие решения приняты и почему, что осталось, на чём споткнулись.

## 2. Записать

Новая запись — **сверху**, сразу после вводного абзаца, перед первой `## `. Формат как у соседних
записей:

```markdown
## <YYYY-MM-DD> — Модуль <N>, фаза <N>, шаг <N>: <тема> (ветка `<ветка>`)

**Сделано.** Что изменено (файлы, коммиты `abc1234`), чем проверено (`npm run check` — N тестов,
скриншоты).

**Решение.** Что выбрали и почему; что отвергли.

**Дальше.** Следующий шаг одной-двумя фразами.

**Ловушки.** Что сломалось или удивило и как обошли. Нет ловушек — «нет».
```

Правила:

- Только факты, которые видны в git или в разговоре; хэши коммитов — настоящие, из `git log`.
- Незакоммиченное — так и пиши («не закоммичено: …»).
- Первые 2–3 строки записи должны стоять сами по себе: hook `SessionStart` при сжатии обрезает
  запись до бюджета 3 КБ.
- Меняй только `docs/memory.md`. Не коммить — для этого `/lib-commit`.

## 3. Ответ

Покажи добавленную запись целиком и одну строку: `Записано в docs/memory.md — закоммитить: /lib-commit`.
