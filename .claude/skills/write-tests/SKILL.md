# Тесты первыми (TDD)

Порядок обязателен: красный тест → минимальный код → рефакторинг. Код правила не пишется,
пока нет падающего теста на него.

## 1. Перечислить случаи

До кода выпиши списком, что проверяешь:

- основной сценарий (книга выдана, возврат принят);
- границы: лимит ровно N и N+1, срок ровно сегодня / вчера / завтра, последний свободный экземпляр;
- ожидаемые отказы — с конкретным кодом (`NO_FREE_COPIES`, `LOAN_LIMIT_REACHED`, ...);
- для API — ещё невалидный вход (zod) → `400`, отказ домена → `4xx` с кодом.

## 2. Написать падающие тесты

- Файл: `tests/unit/<модуль>.test.ts` (модуль — имя файла из `src/domain/` или маршрута).
- Имена тестов — на английском и описывают поведение:
  `it('rejects loan when reader reached the limit')`.
- Время — фиксированное: `const now = new Date('2026-10-17T10:00:00Z')`, передаётся в функцию.
  `new Date()` без аргумента и `vi.useFakeTimers()` вместо параметра `now` — нельзя.
- Отказ проверяй по коду, а не по тексту сообщения.
- Тесты домена — без Express, `fs` и моков хранилища: только вход и результат функции.

Шаблон для домена:

```ts
import { describe, expect, it } from 'vitest';
import { checkoutBook } from '../../src/domain/loans.js';

describe('checkoutBook', () => {
  const now = new Date('2026-10-17T10:00:00Z');

  it('rejects loan when no free copies left', () => {
    const result = checkoutBook({ book, reader, activeLoans, now });

    expect(result).toEqual({ ok: false, code: 'NO_FREE_COPIES' });
  });
});
```

Шаблон для API — как в `tests/unit/health.test.ts`: `request(createApp()).post(...)`.

## 3. Убедиться, что тест красный по нужной причине

```bash
npx vitest run tests/unit/<модуль>.test.ts
```

Тест должен падать на проверке (`expected ... to equal ...`), а не на опечатке или импорте.
Если падает не так — сначала исправь тест.

## 4. Минимальный код, затем рефакторинг

- Пиши ровно столько кода, чтобы тесты позеленели; затем рефакторинг при зелёных тестах.
- В конце — `npm run check`.

## Запрещено

- `.skip`, `.only`, `it.todo` вместо теста, ослабление проверок (`toBeTruthy` вместо точного значения).
- Править или удалять тест, чтобы он прошёл, вместо исправления кода.
- Писать тесты после кода «для покрытия».
