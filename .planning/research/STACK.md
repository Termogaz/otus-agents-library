### 1. Память агента между сессиями

| Технология | Версия | Назначение | Почему |
|------------|--------|------------|--------|
| **claude-mem** (`thedotmack/claude-mem`) | 15.0.1 (npm, 2026-10-20), Apache-2.0 | Автоматическая эпизодическая память: наблюдения за tool-вызовами сжимаются LLM-наблюдателем, пишутся в SQLite + Chroma, подмешиваются в начало следующей сессии; поиск через MCP-инструменты `search` → `timeline` → `get_observations` | Названа в тексте ДЗ прямо. Ставится на уровне пользователя, не затрагивает `package.json`, `package-lock.json` и зависимости проекта. Данные лежат в `~/.claude-mem/`, вне репозитория, и в публичный репозиторий не попадут |
| **Встроенная auto memory** Claude Code | входит в 2.1.308 | Заметки, которые Claude пишет сам (предпочтения, поправки); первые 200 строк / 25 КБ `MEMORY.md` грузятся каждую сессию | Уже включена и работает. Не отключать. Хранит «как работать с этим человеком», а не «что случилось в проекте» |
| **`docs/memory.md`** (журнал сессий) | уже в git, 419 строк | Курируемая память в git: сделано / решение / дальше / ловушки | Единственная память, видимая проверяющему. Этот слой остаётся «аналогом» из ДЗ и запасным вариантом, если claude-mem не взлетит на WSL |
| **GSD `STATE.md` + `/gsd-pause-work` / `/gsd-resume-work`** | gsd-core 1.18.0 | Позиция в проекте и ручной хендофф (`.planning/HANDOFF.json` + `.continue-here.md`) | Это уже установлено. Закрывает «где мы остановились» на уровне фаз |

**Установка claude-mem (требует согласия автора, это плагин вне проекта):**

```bash
# Прокси WSL ломает npm — запускать без переменных прокси (правило AGENTS.md)
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  CLAUDE_MEM_TELEMETRY=0 DO_NOT_TRACK=1 \
  npx claude-mem@15.0.1 install --provider claude
# перезапустить Claude Code, затем проверить:
npx claude-mem doctor
```

Почему так:

- **`npx claude-mem install` — единственный документированный рекомендуемый путь.** Он ставит Bun (если нет), кладёт launcher в `~/.local/bin/claude-mem`, регистрирует плагин и hooks. Маршрут `/plugin marketplace add thedotmack/claude-mem` тоже работает, но в первой сессии контекста памяти может не быть: launcher ещё компилируется.
- **НЕ `npm install -g claude-mem`.** Это только SDK-библиотека, hooks и worker она не регистрирует.
- **`--provider claude`** означает, что наблюдатель работает на вашем Anthropic-плане (модель сжатия по умолчанию `claude-haiku-4-5-20251001`). Входа в сторонний сервис нет, и сессионные данные не уходят на шлюз cmem.ai. По умолчанию установщик предлагает `CMEM Pro` (шлюз cmem.ai, 30 дней триала) с авторизацией через браузер. Это хуже для приватности и лишний аккаунт. Цена выбора: наблюдатель тратит лимиты плана (есть защита: пауза при 95% 5-часового и 93% недельного окна).
- **Телеметрия включена по умолчанию** (анонимные счётчики, ошибки). Отключается `CLAUDE_MEM_TELEMETRY=0` / `DO_NOT_TRACK=1` / `npx claude-mem telemetry disable`. Проверка: `npx claude-mem telemetry status`.
- **Закрепить версию `@15.0.1`.** Мажорные 14.0.0 (2026-10-17) и 15.0.0 (2026-10-20) вышли с разницей в 3 дня, всего 40+ минорных релизов за шесть недель. Менять версию «по дороге» нельзя. То, что установщик уважает закрепление версии в `npx claude-mem@x.y.z`, не проверялось. После установки сверить `claude plugin list`.
- **Побочные эффекты вне проекта** (записать в README «Модуль 2» и в `docs/memory.md`): `~/.claude-mem/` (БД, `settings.json`, логи), `~/.local/bin/claude-mem`, `~/.bun`, фоновый worker. Порт по формуле `37700 + (uid % 100)`; для uid 1000 это 37700, переопределяется `CLAUDE_MEM_WORKER_PORT`.
- **Тонкая настройка в `~/.claude-mem/settings.json`:** `CLAUDE_MEM_CONTEXT_OBSERVATIONS` по умолчанию 50 (подмешивается в каждый старт сессии). Для проекта с 200k-окном снизить до 20–30, иначе claude-mem сам съедает контекст, который мы экономим.
- **Приватность.** Всё внутри `<private>…</private>` не сохраняется. Авто-редакция секретов (`docs.claude-mem.ai/usage/auto-redaction`) опциональна и по умолчанию выключена. Включить стоит. Наши hooks `protect-files` и deny-правила не пускают агента в `.env*`, но claude-mem видит весь вывод инструментов.

**Проверка работы памяти между сессиями (для скриншота ДЗ):**

1. Сессия A: попросить агента выполнить небольшое осмысленное действие (например, разобрать `.planning/codebase/CONCERNS.md`). Закрыть.
2. Сессия B: спросить «что мы делали в прошлой сессии про CONCERNS?» и вызвать `search(query="CONCERNS", limit=10, orderBy="date_desc")`. Это тот же поиск, который описан в документации claude-mem.
3. Дополнительно: `curl http://127.0.0.1:37700/api/search?query=CONCERNS` (порт сверить в `~/.claude-mem/settings.json`) и веб-просмотрщик на `/viewer`.
4. Измерить цену: `claude plugin details claude-mem` показывает строку `Always-on`, сколько токенов плагин добавляет в каждую сессию. Эти цифры годятся и для скриншота usage.

#### Слои памяти (чтобы не плодить источники правды)

| Слой | Что хранит | Кто пишет | Где | В git |
|------|-----------|-----------|-----|-------|
| Auto memory | предпочтения и поправки пользователя | Claude сам | `~/.claude/projects/.../memory/` | нет |
| claude-mem | эпизоды: что делали, какие файлы, что сломалось | hooks + наблюдатель | `~/.claude-mem/` | нет |
| `docs/memory.md` | итоги шагов, решения, ловушки (вручную, по правилу AGENTS.md) | человек + агент | репозиторий | да |
| GSD `.planning/` | позиция в проекте, roadmap, решения (`PROJECT.md` Key Decisions) | GSD | репозиторий | да |

Правило: решения и план живут только в `.planning/` (единый источник плана). claude-mem — это поиск по истории, а не источник правды. Если решение осело только в claude-mem, значит, его потеряли.

### 2. Быстрые команды

| Технология | Версия | Назначение | Почему |
|------------|--------|------------|--------|
| **Skills** (`.claude/skills/<имя>/SKILL.md`) | входят в 2.1.308 | Проектные «быстрые команды»: `/<имя>` | Slash-commands и skills объединены: `.claude/commands/*.md` работают, но для нового кода рекомендуются skills (можно класть вспомогательные файлы, есть все поля frontmatter). В проекте уже два skills (`write-tests`, `review-step`), тот же формат |
| **GSD-команды** (`/gsd-fast`, `/gsd-quick`, `/gsd-progress`, `/gsd-next`, `/gsd-pause-work`, `/gsd-resume-work`) | gsd-core 1.18.0 | Готовый набор быстрых команд для цикла | 72 команды уже установлены. Свои команды дублировать с ними не надо, но файлы GSD лежат вне git (`.claude/commands/gsd-*` в `.gitignore`), поэтому как «настроенные нами» быстрые команды они не засчитаются |

Конструкция проектных skills (подтверждено документацией skills):

- `disable-model-invocation: true` для команд, которые запускает только человек (чтобы агент не запускал их сам).
- `allowed-tools: Bash(npm run check)` и подобные: заранее разрешённые инструменты на время вызова.
- Динамический контекст через `` !`команда` ``: вывод подставляется до того, как модель увидит промпт. Упавшая команда **отменяет весь вызов**, поэтому добавлять `|| true`. Команды проходят через permissions.
- Аргументы: `$ARGUMENTS`, `$0`, именованные через `arguments:`.
- Имена: проектный skill с именем встроенной команды её переопределяет. **Не называть** `/checkpoint` (алиас `/rewind`), `/compact`, `/context`, `/usage`, `/memory`, `/recap`. Брать префикс проекта, например `/lib-status`, `/lib-handoff`, `/lib-check`.
- Skills с `context: fork` выполняются в subagent: правки не откатываются через `/rewind` (если fork фоновый).

Кандидаты (по одной строке в README; реализацию решает фаза): `/lib-status` (ветка + `git status -sb` + позиция в `.planning/STATE.md` + последние 5 записей `docs/memory.md`), `/lib-check` (`npm run check`, краткий итог), `/lib-handoff` (дописать запись в `docs/memory.md` по шаблону «Сделано / Решение / Дальше / Ловушки» перед `/clear` или `/compact`).

### 3. Auto hooks

| Технология | Версия | Назначение | Почему |
|------------|--------|------------|--------|
| **Hooks в `.claude/settings.json`** | Claude Code 2.1.308 | Детерминированные автоматические действия | Закоммиченный файл — доказательство для проверяющего. Hooks из разных файлов настроек складываются (проверить `/hooks`), поэтому GSD в `settings.local.json` не конфликтует |
| **`tsx`** | ^4.23.15 (уже devDependency) | Запуск hook-скриптов на TypeScript | Паттерн ДЗ-1: `"$CLAUDE_PROJECT_DIR"/node_modules/.bin/tsx .claude/hooks/<имя>.ts`, логика покрыта unit-тестами Vitest. Новых зависимостей нет |

**Что умеет каждое событие (по официальной документации hooks) и что с ним делать:**

| Событие | Матчеры | Может ли добавить контекст | Может ли блокировать | Решение для проекта |
|---------|---------|---------------------------|----------------------|--------------------|
| `SessionStart` | `startup`, `resume`, `clear`, `compact`, `fork` | **Да**: stdout как простой текст или `hookSpecificOutput.additionalContext` (до 10 000 символов) | нет | **Использовать.** Скрипт `session-start.ts`: ветка, `git status -sb`, голова `.planning/STATE.md`, последний чекпоинт. Для `compact` — то же самое, это и есть «переинжекция после сжатия» |
| `PreCompact` | `manual`, `auto` | **Нет** (вывод игнорируется; `systemMessage` отбрасывается) | **Да**: exit 2 или `decision: "block"` | **Использовать как чекпоинт**: записать состояние на диск до сжатия. Не блокировать (блок авто-сжатия перед лимитом = ошибка API) |
| `PostCompact` | `manual`, `auto` | Нет | Нет | **Использовать**: поле `compact_summary` содержит итоговое резюме. Сохранить его рядом с чекпоинтом — это материал для скриншота «после» |
| `Stop` | без матчера | да (`additionalContext`) | да (`decision: "block"` продолжает работу, потолок 8 продолжений подряд) | **Не добавлять.** Срабатывает каждый ход, риск зацикливания, GSD уже вешает сюда `gsd-context-monitor` |
| `UserPromptSubmit` | без матчера | да | да | **Не добавлять.** claude-mem уже использует это событие. Лишние hooks на каждый промпт = лишняя задержка |
| `SessionEnd` | причина выхода | нет | нет | **Не использовать**: общий бюджет 1.5 с, ничего надёжного не успеть |

Где сохранять чекпоинт из `PreCompact`/`PostCompact`: в `.local/checkpoints/` (каталог `.local/` уже в `.gitignore`). В git кладём скрипты и тесты, а не рантайм-данные. Для скриншота и README достаточно содержимого файла.

Заготовка конфигурации (в закоммиченный `.claude/settings.json`; править его может только человек или с явным согласием: поймано в `CONCERNS.md`, что агент умеет править настройки):

```json
{
  "autoCompactWindow": 200000,
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume|clear|compact",
        "hooks": [{ "type": "command", "timeout": 10,
          "command": "\"$CLAUDE_PROJECT_DIR\"/node_modules/.bin/tsx \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/session-start.ts" }] }
    ],
    "PreCompact": [
      { "hooks": [{ "type": "command", "timeout": 10,
          "command": "\"$CLAUDE_PROJECT_DIR\"/node_modules/.bin/tsx \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/checkpoint.ts" }] }
    ],
    "PostCompact": [
      { "hooks": [{ "type": "command", "timeout": 10,
          "command": "\"$CLAUDE_PROJECT_DIR\"/node_modules/.bin/tsx \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/checkpoint.ts" }] }
    ]
  }
}
```

Замечания по эксплуатации:

- Хук читает JSON со stdin. Поле `hook_event_name` различает `PreCompact` и `PostCompact`, `trigger` — `manual`/`auto`.
- Падение хука не блокирует действие (код не 0 и не 2 — «не блокирующая ошибка»). `"onFailure": "block"` (с v2.1.295) здесь **не** ставить: чекпоинт не должен ронять сжатие.
- Задержка: у GSD уже 18 hooks, замерить суммарную задержку (шаг в `docs/memory.md` от 2026-10-22 это просит). `tsx` стартует дольше голого Node. Для `SessionStart` это терпимо, для частых событий (`PostToolUse`) нужен `node` без компиляции.
- Хук `SessionStart` GSD (`gsd-session-state.sh`) делает похожую работу (голова `STATE.md`), но включается только `hooks.community: true` и лежит вне git. Не включать оба одновременно, иначе контекст продублируется: выбрать наш закоммиченный скрипт.

### 4. Управление контекстом

| Технология | Версия | Назначение | Почему |
|------------|--------|------------|--------|
| **Автосжатие** (`autoCompactWindow`) | 2.1.308 | Порог, при котором Claude Code сжимает беседу сам | У моделей с нативным 1M порог по умолчанию около 967K токенов. На демонстрации и в обычной работе автосжатие не сработает. Параметр `"autoCompactWindow": 200000` в закоммиченном `settings.json` делает поведение воспроизводимым и совпадает с допущением GSD (`context_window` по умолчанию 200k, глубина чтения артефактов зависит от неё). Допустимо от 100K до 1M. Альтернативы: `/autocompact 200k` (пишет в пользовательские настройки), `claude --autocompact 200k` (один запуск), `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000` (скрипты; без суффикса это токены, а не тысячи). Приоритет: переменная окружения > сохранённое `/autocompact` > `autoCompactWindow` |
| **`/compact [инструкции]`** | встроено | Сжатие вручную с фокусом | `CLAUDE.md`/`AGENTS.md`, auto memory и описания skills перечитываются с диска и переживают сжатие. `paths:`-rules и вложенные `CLAUDE.md` НЕ переживают (они были в истории). Правила, критичные всегда, не должны зависеть от `paths:` |
| **`/rewind`** (алиасы `/checkpoint`, `/undo`; `Esc Esc`) | встроено | Чекпоинты: откат кода и/или беседы; «Summarize from here / up to here» — точечное сжатие | Чекпоинт создаётся на каждый ход, хранятся последние 100, живут до ~30 дней (`cleanupPeriodDays`). **Не отслеживает** правки через Bash (`rm`, `mv`, `sed -i`) и правки subagent'ов. **Не заменяет git** |
| **`/context`** | встроено | Разбивка контекста по категориям, какие `CLAUDE.md`/memory загружены, подсказки | Основа скриншота «до/после» |
| **`/usage`** (алиасы `/cost`, `/stats`) | встроено | Стоимость сессии, лимиты плана, статистика | Основа скриншота usage |
| **statusLine** | встроено | Постоянная строка: `context_window.used_percentage`, `cost.total_cost_usd`, `rate_limits.five_hour.used_percentage` | Видно заполнение контекста в реальном времени. Скрипт получает JSON на stdin. `jq` в системе нет |
| **GSD `gsd-context-monitor` + `gsd-statusline.js`** | gsd-core 1.18.0 | Агент **сам** узнаёт о нехватке контекста: при остатке ≤ 35% приходит WARNING («заканчивай текущую задачу»), при ≤ 25% CRITICAL («остановись, сохрани состояние»), инжекция через `additionalContext` | Хуки монитора уже зарегистрированы, но без statusline они ничего не получают (bridge-файл пишет только statusline). Это самый готовый «инструмент управления контекстом» в окружении |
| **`/gsd-pause-work` / `/gsd-resume-work`** | gsd-core 1.18.0 | Чекпоинт уровня проекта: `HANDOFF.json` + `.continue-here.md`, восстановление в новой сессии | Переживает `/clear` и закрытие сессии, лежит в `.planning/` (в git) |

**Решение по statusline.** Подключить `gsd-statusline.js` через `.claude/settings.local.json` (рядом с остальными GSD-хуками):

```json
{ "statusLine": { "type": "command",
  "command": "node \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/gsd-statusline.js" } }
```

Так оживает `gsd-context-monitor`. Цена: этот файл вне git, проверяющий увидит только скриншот. Если нужна закоммиченная версия, нужен собственный короткий скрипт на Node в `.claude/hooks/statusline.ts`, но он не пишет bridge-файл и мониторы GSD с ним не заработают. Рекомендация: GSD-вариант как основной (минимум нового кода), описание и скриншот в README. **Перед включением прочитать вывод `gsd-statusline.js` в сессии**: проверка, что он не ломает отрисовку (скрипт при падении выдаёт пустую строку, не ошибку).

**Что считать «до и после» для скриншота ДЗ** (протокол, чтобы сравнение было честным):

1. **До** (без внедрения): свежая сессия, одна и та же нагрузка (например, прочитать `.planning/codebase/*.md` и пересказать ограничения). `/context` + `/usage` → скриншот 1. Если окно 1M, заполнение будет в единицах процентов, и сравнивать нечего. Поэтому «до» снимать с `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000`, но без hooks, statusline и чекпоинтов, либо явно описать базу как «окно 1M, автосжатие около 967K».
2. **После**: та же нагрузка с внедрёнными `autoCompactWindow`, statusline, hooks. Дойти до сжатия (ручной `/compact` с фокусом достаточно; автосжатие — если сумеем набрать 200K). `/context` после сжатия + строка statusline + содержимое чекпоинта и `compact_summary` → скриншот 2.
3. В README зафиксировать, что именно сравнивается. «До» и «после» должны отличаться тем, что внедрили, а не нагрузкой.

## Чего НЕ использовать

| Не использовать | Почему | Вместо этого |
|-----------------|--------|--------------|
| `npm install -g claude-mem` | Ставит только SDK-библиотеку, hooks и worker не регистрируются: «установлено», но не работает | `npx claude-mem@15.0.1 install --provider claude` |
| claude-mem с провайдером по умолчанию (CMEM Pro, шлюз cmem.ai) | Вход через браузер, данные идут на сторонний шлюз, платная подписка после триала | `--provider claude` (на вашем плане), телеметрию выключить |
| Любые зависимости в `package.json` ради памяти или контекста | Запрет AGENTS.md и PROJECT.md без согласования | Всё из списка выше ставится вне проекта или уже есть |
| Hook на `Stop` или `UserPromptSubmit` «для надёжности» | Срабатывают на каждый ход; `Stop` рискует зациклиться (потолок 8 продолжений); дублируют claude-mem и GSD | `SessionStart` (+`compact`), `PreCompact`, `PostCompact` |
| Блокировка `PreCompact` | Для авто-сжатия перед лимитом пропускает сжатие, для сжатия после ошибки лимита — запрос падает | Только запись чекпоинта |
| Рассчитывать, что `/rewind` откатит Bash-правки | Чекпоинты их не отслеживают | git (коммит перед рискованным шагом), ветки `feat/*` |
| `jq` в скриптах hooks и statusline | В системе нет | `node -e` / TypeScript |
| Правки `.claude/settings.json` агентом без подтверждения | Находка `CONCERNS.md`: hook `protect-files` его не защищает | Правит человек или с явным согласием, проверка через `/hooks` |
| `--dangerously-skip-permissions` (совет учебника GSD) | Противоречит политике permissions проекта | Режим `acceptEdits` + allow/ask/deny из ДЗ-1 |
| Включать одновременно `gsd-session-state.sh` (`hooks.community`) и свой `session-start.ts` | Двойная инжекция одного и того же | Один источник: наш закоммиченный скрипт |
| Полагаться на то, что `paths:`-правила переживут сжатие | Они подгружаются в историю и сжимаются вместе с ней | Критичное — в корневой `AGENTS.md`/`CLAUDE.md` |

## Варианты по условиям

**Если claude-mem не устанавливается (Bun/Chroma/демон на WSL, нет согласия автора):**
- Запасной вариант «аналога»: auto memory + `docs/memory.md` + `session-start.ts`, который подмешивает свежие записи журнала. Всё в git, воспроизводимо.
- Для скриншота «память между сессиями» достаточно: сессия A пишет запись, сессия B на старте цитирует её из hook-контекста.

**Если `autoCompactWindow: 200000` в закоммиченном `settings.json` нежелателен (влияет на все сессии проекта и всех, кто клонирует):**
- Использовать `/autocompact 200k` (в пользовательские настройки) или `claude --autocompact 200k` для замеров, а в `settings.json` оставить только hooks.

**Если нужен реальный набор до 200K токенов для автосжатия:**
- Прогнать фазу GSD (map-codebase, research) в одной сессии без `/clear`: GSD сам порождает subagent'ов, их выводы сильно разбавляют контекст. Другой путь: уменьшить окно до 100K (минимум допустимого).
