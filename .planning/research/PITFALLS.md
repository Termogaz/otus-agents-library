# Pitfalls Research

**Domain:** агентно-ориентированный пайплайн разработки вокруг Claude Code (память агента, SessionStart/PreCompact hooks, управление контекстом, GSD в существующем репозитории) — веха ДЗ-2 проекта «Библиотека»
**Researched:** 2026-10-22
**Confidence:** MEDIUM — факты о репозитории и локальной установке GSD проверены по файлам (HIGH); поведение Claude Code hooks и compaction — по официальной документации, одна выборка (MEDIUM); поведение claude-mem — по документации проекта и issue-трекеру, часть утверждений от одного автора (LOW, помечены).

Условные обозначения уверенности у каждого пункта: **[HIGH]** — проверено по файлам репозитория или локальному коду GSD; **[MEDIUM]** — официальная документация Claude Code / claude-mem; **[LOW]** — одна сторонняя публикация или вывод по аналогии, проверить руками до опоры на него.

Фазы в разделе «Pitfall-to-Phase Mapping» названы по шагам ДЗ-2 (`docs/homework-2.md`): **Ф1** GSD-инициализация и единый источник плана, **Ф2** память агента, **Ф3** быстрые команды и auto hooks, **Ф4** управление контекстом, **Ф5** Discovery «продление и пени», **Ф6** README, PR, `npm run check`. Рекомендация для roadmap: внутри Ф1 сделать «hardening секретов» (пит. 1, 15) до Ф2.

## Critical Pitfalls

### Pitfall 1: Память сохраняет секреты и персональные данные дословно

**What goes wrong:**
claude-mem подключается к hooks `PostToolUse`/`UserPromptSubmit` и сохраняет результаты инструментов (вывод `Bash`, `Read`, ответы MCP) в локальную SQLite `~/.claude-mem/claude-mem.db`, а часть текста уходит модели-наблюдателю для сжатия. Если агент хоть раз выведет содержимое `.env`, `data/library.json` (контакты читателей — персональные данные) или токен из `curl`/логов, оно окажется в БД и будет подмешиваться в будущие сессии. Опциональная редакция секретов, по сообщению одного тестера, выключена по умолчанию (`CLAUDE_MEM_REDACT_ENABLED: 'false'`) и пропустила 6 из 10 тестовых ключей **[LOW]**; официальная страница установки не описывает ни редакцию, ни исключение путей, а тег `<private>` — единственный документированный способ не сохранять фрагмент **[MEDIUM]**.

**Why it happens:**
Защита проекта от чтения `.env` — эвристика по префиксам (`Bash(cat .env*)`), а `CONCERNS.md` уже нашёл обходы: `cat ./.env`, `grep x .env`, `less .env`; subagent `reviewer` по hook'у может читать `.env` через `cat` с относительным путём **[HIGH]**. Единственный широкий перехватчик — `gsd-secret-read-guard.js` — подключён только в `.claude/settings.local.json` (в `.gitignore`), то есть не в git и не виден проверяющему **[HIGH]**. Память превращает любой единичный обход в постоянную утечку.

**How to avoid:**
1. До установки памяти закрыть находки `CONCERNS.md` про секреты (Ф1, security-checklist): `Read(**/.env*)`, deny для `git add -f`, basename-проверка `.env*` в `reviewer-readonly.ts`, тесты на обходы в `tests/unit/protect-files.test.ts`.
2. Включить редакцию секретов, если она есть в установленной версии, и **не полагаться на неё**: канарейка-тест — положить в вывод `echo` фальшивый ключ `sk-test-CANARY-123`, выполнить, затем `sqlite3`/поиск по `~/.claude-mem/claude-mem.db` — должно быть пусто.
3. Отключить облачную часть: `CLAUDE_MEM_ONLINE_OPTIN=false`, не включать Cloud Sync, провайдер — локальный/собственный, не шлюз `cmem.ai` **[MEDIUM]**.
4. Не печатать `data/library.json` целиком в сессии; для проверок использовать выборки без контактов.
5. `~/.claude-mem/` не копировать в репозиторий и не скриншотить БД; в README описать, что и где хранится.
6. Запасной вариант («или аналог» из ДЗ): `docs/memory.md` + `.planning/STATE.md` + `/gsd-pause-work` HANDOFF — без фонового процесса и БД; если п. 2 даёт утечку, выбирать его.

**Warning signs:**
Канарейка находится в БД; в инжектируемом контексте SessionStart виден фрагмент `.env`/контактов; `grep -r "sk-" ~/.claude-mem` даёт совпадения.

**Phase to address:** Ф1 (hardening) и Ф2 (проверка канарейкой до принятия решения «оставляем»).

### Pitfall 2: Фоновый worker памяти ломается из-за окружения (Node/Bun/uv, порт, прокси) и тихо отключает память

**What goes wrong:**
claude-mem — не просто плагин: это hooks, вызывающие `claude-mem hook claude-code <event>` (launcher на PATH), фоновый worker (по умолчанию порт 37777, файлы `~/.claude-mem/.worker.pid`, `.worker.port`, логи `logs/worker-*.log`), Bun (ставится автоматически, если нет) и `uv` для Chroma-векторного поиска; требуются Node ≥ 20 и Claude Code ≥ 2.1.139 **[MEDIUM]**. Известные сбои: `bun: command not found` в hooks (#565), worker не стартует на порту 37777 (#380), осиротевший worker держит порт/PID-файл и блокирует каждый prompt до ручной смены порта (#2899, ссылки на #729 «hooks hard-block whole session» и #2292 «zombie worker») **[MEDIUM, версии разные — сверить с установленной]**; если hooks не активны, сессия лишь пишет «memory hooks are not active», а память просто пустая **[MEDIUM]**.

**Why it happens:**
Для этого проекта добавляются три специфичных усилителя **[HIGH — ловушки зафиксированы в `AGENTS.md`/`docs/memory.md`]**:
- **Прокси.** `npm`/`npx`/Playwright за локальным HTTP-прокси падают (`ECONNRESET`, `Timed out waiting 60000ms from config.webServer`). Тот же класс ошибок ожидаем для `npx claude-mem install`, `bun install` и health-check worker'а на `127.0.0.1:37777`, если `http_proxy` задан без `NO_PROXY` (вывод по аналогии **[LOW]**).
- **nvm.** hooks запускаются в неинтерактивной оболочке без nvm; GSD обошёл это абсолютным путём к Node 24 в `settings.local.json`, а launcher claude-mem и Bun на PATH не окажутся сами. Сессия, запущенная до установки, hooks не видит (как с Node 22 в ДЗ-1).
- **WSL.** Процессы worker'а живут вне сессии Claude Code и переживают её; `pkill`/перезапуск WSL оставляет устаревшие PID/порт-файлы.

**How to avoid:**
1. Перед установкой: `node -v` (≥ 24 для GSD), `which uv` (есть: `~/.local/bin/uv`), `claude --version` ≥ 2.1.139; ставить командой `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY npx claude-mem install`; затем `npx claude-mem doctor`.
2. Прописать `NO_PROXY=127.0.0.1,localhost` для процесса worker'а (либо запускать его через `env -u ...`), чтобы health-check не шёл через прокси.
3. После установки — **новая** сессия Claude Code; проверка hooks через `claude --debug` или `/hooks`.
4. Записать в `docs/memory.md` и README рецепт восстановления: `npx claude-mem repair`, где лежат PID/порт-файлы, как сменить порт.
5. Зафиксировать версию (`npx claude-mem@<версия>`), как сделано для GSD (`@opengsd/gsd-core@1.18.0`) — не `@latest`.
6. Решить заранее критерий отката: если worker нестабилен после одной попытки починки — перейти на запасной вариант из Pitfall 1 (п. 6), а не тратить фазу на отладку.

**Warning signs:**
Сессия стартует с задержкой; в начале нет блока памяти; `~/.claude-mem/logs/` пуст или полон ошибок; в выводе `ss -ltnp | grep 37777` нет слушателя либо слушает чужой процесс.

**Phase to address:** Ф2.

### Pitfall 3: Установка памяти правит конфигурацию вне репозитория и подмешивает контекст, который проверяющий не увидит

**What goes wrong:**
Плагин claude-mem ставится в пользовательский (user-scope) уровень: его hooks и `hooks.json` не лежат в git, работают во **всех** проектах на машине и ловят сессии всех проектов. Проверяющий ДЗ по репозиторию не увидит ни установки, ни hooks; то же верно для GSD-hooks в `settings.local.json` **[HIGH]**. Дополнительно память меняет «базовый» размер контекста (инъекция наблюдений на старте) — скриншоты usage «до» и «после» окажутся несопоставимыми, а фоновый наблюдатель может расходовать токены тарифа Anthropic (после 30-дневного пробного периода память «возвращается» на ваш тариф) **[MEDIUM]**.

**Why it happens:**
Критерий ДЗ — «в README описаны результаты для проверки»; настройка вне git не воспроизводима, если не описана.

**How to avoid:**
- В README «Модуль 2» дать воспроизводимую последовательность: версия, команда установки (с `env -u ...`), команда проверки (`doctor`), тестовый сценарий «сессия 1 → факт → новая сессия 2 → агент вспоминает», скриншот.
- Если возможно, ограничить память только этим проектом (проектный scope плагина / отдельный `CLAUDE_MEM_DATA_DIR`) и записать, что остальные проекты не затрагиваются.
- Делать скриншоты usage при одинаковых условиях: память выключена/включена явно указана в подписи; сначала «до» (чистая сессия, `/context`), затем «после».
- Подпись о стоимости: наблюдатель — отдельный фоновый расход, в усage основной сессии не виден.

**Warning signs:**
`git status` чистый после установки (значит, ничего воспроизводимого не добавлено); в README нет версии и команды.

**Phase to address:** Ф2 (установка/описание), Ф4 (сопоставимость скриншотов), Ф6 (README).

### Pitfall 4: Hooks SessionStart/PreCompact конфликтуют с уже установленными hooks и множат задержку

**What goes wrong:**
В `settings.local.json` GSD уже занял: `SessionStart` ×2 (`gsd-check-update.js`, `gsd-session-state.sh`), `PreCompact` (`gsd-context-monitor.js`), `PostToolUse` ×4, `PreToolUse` ×7 (включая `gsd-validate-commit.sh` и `gsd-secret-read-guard.js` на `Bash`) **[HIGH]**. Свои hooks из `settings.json` (`protect-files.ts` на `Edit|Write|Bash`, `format-and-lint.ts`) выполняются параллельно с ними; порядок не гарантирован, а одинаковый обработчик в двух файлах запускается один раз только если описан идентично **[MEDIUM]**. Каждый Node/tsx-hook — отдельный холодный процесс: на каждый `Bash` теперь стартуют минимум три-четыре; `tsx` заметно медленнее чистого Node. SessionStart на `startup/resume/clear` блокирует первый ответ Claude до завершения hooks **[MEDIUM]**.

**Why it happens:**
Два «владельца» hooks (проект и GSD) не знают друг о друге; новый hook добавляют «по образцу» ДЗ-1 (`tsx`).

**How to avoid:**
1. Перед добавлением: `/hooks` и вывод перечня (как в таблице выше) в `docs/` — инвентаризация; новый hook не должен дублировать функцию GSD (`gsd-session-state.sh` уже вставляет голову `STATE.md`, но он **no-op** без `hooks.community: true` в `.planning/config.json` **[HIGH]** — решить осознанно, включать ли, помня, что флаг включает и `gsd-validate-commit.sh`).
2. Новые SessionStart/PreCompact hooks — быстрые: чистый Node/`bash` без `tsx`, явный `timeout` (5–10 с), измерить `time` и сложить с GSD; цель — суммарно ≪ 1 с на `startup`.
3. Никаких сетевых вызовов в SessionStart (у `gsd-check-update.js` он уже есть — фоновый, за прокси может молча не отработать).
4. Матчеры сужать: `SessionStart` с `matcher: "startup|resume|compact"`, не на все источники.
5. Тест на логику в `tests/unit/` (соглашение проекта: hooks покрыты тестами), `npm run check` зелёный (`.claude/hooks` входит в `tsconfig`).

**Warning signs:**
Заметная пауза перед первым ответом; в `claude --debug` hooks завершаются по таймауту; два блока «состояние проекта» в контексте сразу.

**Phase to address:** Ф3.

### Pitfall 5: Контекст из SessionStart обрезается и/или раздувает «базовый» контекст

**What goes wrong:**
Вывод SessionStart hook (stdout, `additionalContext`, `systemMessage`) ограничен 10 000 символов на каждую строку; при превышении Claude получает путь к файлу и превью первых 2 000 символов, **без** просьбы прочитать файл; лимит не настраивается **[MEDIUM]**. При этом на старте уже грузятся: `CLAUDE.md` → `AGENTS.md` (~8 КБ) → **`@docs/plan.md` целиком** (импорт в `CLAUDE.md`), ~72 слэш-команды и ~36 агентов GSD при `.gsd-profile = full`, плюс наблюдения памяти и голова `STATE.md` **[HIGH]**. Критичное (правила, текущий шаг) может остаться за пределами 2 000 символов превью.

**Why it happens:**
Каждый инструмент добавляет «немного полезного контекста» на старте, никто не считает сумму.

**How to avoid:**
- Бюджет: собственный SessionStart hook ≤ 2–3 КБ (путь к чек-пойнту + 5–10 строк «текущее состояние / следующий шаг»), детали — ссылкой на файл, который агент читает сам.
- Уменьшить фон: профиль GSD минимальнее (`/gsd-surface`, профиль вместо `full`), заменить `@docs/plan.md` в `CLAUDE.md` указателем на `.planning/ROADMAP.md` (см. Pitfall 11) — только после согласования с автором (правило `AGENTS.md`).
- Измерять `/context` до и после каждого нового источника; цифры — в README (это и есть материал для скриншотов usage).

**Warning signs:**
В сессии виден «Output truncated, saved to file»; `/context` показывает сотни токенов Skills/Memory до первого сообщения; агент не знает того, что hook «вроде бы вставил».

**Phase to address:** Ф3 (бюджет hook), Ф4 (измерение).

### Pitfall 6: Путают, что умеет PreCompact, и теряют «чек-пойнт» при сжатии

**What goes wrong:**
(а) Ожидают, что вывод PreCompact попадёт в контекст после сжатия — это не так: контекст после compaction добавляют SessionStart hooks с `matcher: "compact"`, а hooks, добавленный контекст которых был раньше, суммируются вместе с разговором **[MEDIUM]**; GSD сам отмечает, что на PreCompact конверт `additionalContext` не принимается **[HIGH]**. (б) PreCompact с `exit 2` **блокирует** compaction (matchers `manual`/`auto`) — ошибка скрипта с кодом 2 или `decision: block` может не дать автосжатию сработать, и сессия упрётся в лимит **[MEDIUM]**. (в) Чек-пойнт «в памяти разговора» без записи на диск не переживёт сжатие.

**Why it happens:**
Название «PreCompact» подсказывает «подготовить контекст», а механизм возврата — другой.

**How to avoid:**
- Схема: `PreCompact` (только сохранить состояние на диск, всегда `exit 0`, без `decision`) → `SessionStart` с `matcher: "compact"` (короткий вывод «прочитай `<путь чек-пойнта>`, последний шаг: …»). Протестировать оба направления в новой сессии: `/compact` вручную и автосжатие.
- Источник чек-пойнта — файл, не память модели: `.planning/STATE.md`/HANDOFF от `/gsd-pause-work` или `docs/memory.md` (формат «сделано / решение / дальше / ловушки» уже есть в `AGENTS.md`). Не изобретать четвёртое хранилище.
- Ручное сжатие с фокусом (`/compact сохрани: текущий шаг, решения, незакоммиченные файлы`) — для демонстрации в README.

**Warning signs:**
После `/compact` агент спрашивает «над чем мы работали»; сессия не сжимается автоматически; в `claude --debug` PreCompact завершается с кодом 2.

**Phase to address:** Ф3 (механика hooks), Ф4 (проверка и скриншоты).

### Pitfall 7: После compaction пропадают path-scoped rules и решения «из разговора»

**What goes wrong:**
Что **переживает** сжатие: системный prompt, корневой `CLAUDE.md` (а с ним `AGENTS.md` через `@`) и rules без `paths:` — перечитываются с диска; авто-память; описания skills; до 5 последних прочитанных/изменённых файлов (файл > 5 000 токенов возвращается только ссылкой); тела вызванных skills — до 5 000 токенов каждое и 25 000 суммарно. Что **теряется**: rules с `paths:` и вложенные `CLAUDE.md` (загружаются «по требованию» при чтении файла и при сжатии суммируются); всё, что сказано в разговоре и не записано; контекст, ранее добавленный hooks **[MEDIUM]**. Здесь это `.claude/rules/domain.md` (`paths: src/domain/**`) и `.claude/rules/e2e.md` — именно правила «домен не импортирует Express/fs», «в e2e без `waitForTimeout`» исчезнут после сжатия, пока агент заново не откроет файл из соответствующей папки **[HIGH]**.

**Why it happens:**
Rules с `paths:` подгружаются в историю сообщений, а не в «фиксированную» часть контекста.

**How to avoid:**
- Для демонстрации ДЗ: сценарий «правка в `src/domain/` → `/compact` → правка в `src/domain/` без чтения соседних файлов → правило соблюдено/нет» и вывод по результату в README.
- Критичные инварианты (domain-purity) продублировать коротко в `AGENTS.md` (уже частично там) либо снять `paths:` у самых важных rules — только после согласования.
- Решения и открытые вопросы фиксировать в файлах до `/compact` (см. Pitfall 6).

**Warning signs:**
После сжатия агент импортирует `fs`/Express в `src/domain/`, использует `waitForTimeout` в e2e; hook `protect-files`/линтер ловит то, что rule предотвращал бы.

**Phase to address:** Ф4.

### Pitfall 8: Нечем «показать» автосжатие и usage — монитор контекста GSD молчит

**What goes wrong:**
(1) `gsd-context-monitor.js` читает метрики из «моста» `/tmp/claude-ctx-{session_id}.json`, который пишет statusline-hook GSD; в `settings.json` и `settings.local.json` ключа `statusLine` **нет**, в `~/.claude/settings.json` тоже не найден — значит, предупреждения WARNING (≤ 35% остатка) и CRITICAL (≤ 25%) могут не появиться никогда, при `context_guard_mode: "warn"` и `hooks.context_warnings: true` в конфиге **[HIGH — по файлам; поведение при отсутствии моста выведено из заголовка скрипта]**. (2) Окно контекста у современных моделей до 1M токенов, порог автосжатия зависит от модели и настройки; за короткую учебную сессию автосжатие может **не случиться вовсе**, и «после» нечего скриншотить **[MEDIUM]**. (3) GSD-hook лишь предупреждает (`warn`) — это не «инструмент управления контекстом» сам по себе.

**Why it happens:**
Автосжатие — внутренняя функция Claude Code, а GSD-монитор — надстройка с неявной зависимостью от statusline.

**How to avoid:**
- Включить statusline GSD (или собственный `statusLine`) и проверить появление файла `/tmp/claude-ctx-*.json` во время сессии; иначе убрать монитор из заявленных результатов.
- Для демонстрации понизить порог: `/autocompact <число токенов>` (настройка окна автосжатия) или вызвать `/compact`; снять `/context` и `/usage` до и после (одна модель, одно окно, подпись с условиями).
- Не писать в README «автосжатие сработало», если сработал ручной `/compact`; честно указывать, что именно показано.

**Warning signs:**

**Warning signs:**

### Pitfall 15: Защитные hooks по-прежнему fail-open, а новые зависят от Node/`tsx`

Безусловный `echo` в `~/.bashrc` (в т.ч. от nvm) портит JSON-вывод hook'а — вывод не начинается с `{` и игнорируется молча **[MEDIUM]**. Проверка: `claude --debug`, строка `Hook output does not start with {`.

### Pitfall 24: Лишний `npx -y` на старте
`.mcp.json` тянет пакет через `npx -y` на каждый холодный старт; за прокси без `env -u` в `args` это уже учтено, но новые инструменты (claude-mem) нужно ставить по тому же принципу — через зафиксированную версию.

### Pitfall 25: Сессия, запущенная до установки, не видит hooks
Как и в ДЗ-1 (Node 22): после установки памяти/GSD/правки `settings.json` нужна новая сессия. Не принимать «не работает» за дефект до перезапуска.

## Technical Debt Patterns

| Shortcut | Immediate Benefit | Long-term Cost | When Acceptable |
|----------|-------------------|----------------|-----------------|
| Оставить `docs/plan.md` и `.planning/ROADMAP.md` параллельно | Нет миграции | Расхождение статусов, агент правит не тот файл | Никогда |
| Включить `hooks.community: true` «чтобы заработал session-state» | Готовая сводка состояния на старте | Включает ещё и `gsd-validate-commit.sh` (блокировка коммитов), дублирует собственный SessionStart | Только после пробы на русских коммитах |
| Писать hooks на `tsx` по образцу ДЗ-1 | Единый стек, типы | Холодный старт, fail-open без `node_modules` | Для политик с тестами; для SessionStart лучше чистый Node/bash |
| `commit_docs: true` без ревью | Каждый артефакт в истории | Шум в PR, английские сообщения | Только на ветке `feat/module-2` с ревью `git log` |
| Не фиксировать версию claude-mem | Быстрая установка | Невоспроизводимость, смена hooks | Никогда |
| Чек-пойнты в `docs/` | Видны проверяющему | Грязное дерево, красный `format:check` | Только если файл форматируется Prettier и пишется вручную |

## Integration Gotchas

| Integration | Common Mistake | Correct Approach |
|-------------|----------------|------------------|
| claude-mem + прокси | `npx claude-mem install` с переменными прокси | `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY ...`, `NO_PROXY=127.0.0.1,localhost` для worker'а |
| claude-mem + nvm | Полагаться на PATH в hooks | Проверить `doctor`; абсолютный путь по образцу GSD, если launcher не находится |
| claude-mem + секреты | Считать редакцию надёжной | Канарейка-тест, `<private>`, закрытые обходы чтения `.env` |
| GSD + `CLAUDE.md` | `--force` или принять второй файл инструкций | Оставить `AGENTS.md` главным; GSD-блок короткий и под маркерами |
| GSD + Prettier/ESLint | Править `format:check` ослаблением конфигов | Игнорировать генерируемое, согласовав с автором; `npm run check` после каждой операции |
| GSD hooks + свои hooks | Дублировать функции, не знать порядок | Инвентаризация `/hooks`; независимые, быстрые, идемпотентные hooks |
| SessionStart + `compact` | Ждать вывод PreCompact в контексте | PreCompact сохраняет, SessionStart `compact` возвращает |
| Statusline + context monitor | Включить `warn` без statusline | Включить statusline и проверить `/tmp/claude-ctx-*.json` |

## Performance Traps

| Trap | Symptoms | Prevention | When It Breaks |
|------|----------|------------|----------------|
| Много Node-процессов на каждый `Bash`/`Edit` (protect-files, validate-commit, secret-read-guard, workflow-guard, prettier+eslint) | Заметная пауза после каждого действия агента | Узкие матчеры, лёгкие скрипты, `timeout` 5–10 с | Уже при 4–7 hooks на событие |
| Блокирующий SessionStart | Пауза перед первым ответом | Только локальные быстрые операции; никаких сетевых вызовов | Любая сетевая задержка/прокси |
| Большой стартовый контекст (AGENTS.md + plan.md + 72 команды + память) | Мало места до автосжатия, дорогие сообщения | Профиль GSD минимальнее, указатель вместо `@docs/plan.md`, бюджет hook'а | Сразу; видно в `/context` |
| Накопление наблюдений памяти | Рост БД, инжекция лишнего | Лимит числа наблюдений, чистка, проверка размера `~/.claude-mem` | Недели работы, не в рамках ДЗ |

## Security Mistakes

| Mistake | Risk | Prevention |
|---------|------|------------|
| Вывод `.env` или `data/library.json` в сессию при активной памяти | Постоянное хранение секрета/ПДн в `~/.claude-mem` | Закрыть обходы из `CONCERNS.md`, канарейка-тест, `<private>` — высокий |
| Агент правит `.claude/settings.json`/hooks | Подмена защит, исполнение команд на старте сессии | `Edit(./.claude/**)` в `ask`/protect-files — высокий |
| Защита только в `settings.local.json` (вне git) | Проверяющий и новый клон её не получают | Дублировать ключевое в `settings.json` или явно описать в security-checklist — средний |
| Облачная синхронизация/шлюз памяти | История сессий уходит третьей стороне | `CLAUDE_MEM_ONLINE_OPTIN=false`, без Cloud Sync, локальный провайдер — высокий |
| Память хранит содержимое веб-страниц | Отравление памяти, инструкции переживают сессию | Не включать веб-инструменты при активной памяти без нужды; сканер инъекций GSD оставить — средний |
| Широкие allow в `settings.local.json` | Неконтролируемые `git commit`, `pkill`, `claude mcp` | Периодический обзор, сузить — средний |
| Сервер API слушает `0.0.0.0` и без аутентификации | Контакты читателей доступны в локальной сети, в т.ч. при проверках с памятью | Вынести в бэклог по `CONCERNS.md`; не делать API доступным публично — средний |

## "Looks Done But Isn't" Checklist

- [ ] **Память:** часто нет проверки в НОВОЙ сессии — убедиться, что агент вспоминает факт, записанный в предыдущей, и что в БД нет канарейки-секрета.
- [ ] **Память:** описана установка вне git — проверить, что в README есть версия, команды с `env -u ...`, `doctor`, восстановление.
- [ ] **SessionStart hook:** выводит ≤ 10 000 символов (в идеале ≤ 3 000) и завершается быстро; проверить `claude --debug`.
- [ ] **PreCompact hook:** всегда `exit 0`, пишет только в игнорируемый путь; возврат контекста — через SessionStart `compact`.
- [ ] **Hooks:** покрыты тестами в `tests/unit/`, `npm run check` зелёный, `git status` чист после сессии.
- [ ] **Автосжатие:** есть доказательство именно автосжатия (или честная подпись «ручной `/compact`»); statusline включён.
- [ ] **usage до/после:** одинаковые условия, подписи, без секретов на скриншоте.
- [ ] **GSD init:** один источник плана; `AGENTS.md`/`CLAUDE.md` согласованы; нет `.claude/CLAUDE.md` с конфликтующими правилами; `docs/plan.md` — указатель.
- [ ] **security-checklist:** включает пункты из `CONCERNS.md` (обходы `.env`, правка `.claude/`, fail-open hooks, `npx -y`) и риски памяти.
- [ ] **Discovery:** есть артефакт с открытыми вопросами; в `src/` нет изменений.
- [ ] **PR:** язык и формат коммитов соответствуют `AGENTS.md`, нет атрибуции агента, `npm run check` зелёный.

## Recovery Strategies

| Pitfall | Recovery Cost | Recovery Steps |
|---------|---------------|----------------|
| Секрет попал в память | HIGH | Остановить worker, удалить запись/БД `~/.claude-mem/claude-mem.db`, перевыпустить секрет, закрыть путь утечки, повторить канарейку |
| Worker завис, порт занят | LOW | `npx claude-mem repair`, удалить устаревшие `.worker.pid`/`.worker.port`, сменить порт, новая сессия |
| Память не работает за прокси | LOW | Переустановка через `env -u ...`, `NO_PROXY`; при повторе — запасной вариант (`docs/memory.md` + `STATE.md`) |
| GSD создал `.claude/CLAUDE.md`/лишние файлы | LOW | `git status`, удалить/сократить, обновить `.gitignore`, записать в `docs/memory.md` |
| GSD закоммитил документы с неверным языком | MEDIUM | Переписать историю локальной ветки до публикации (правило: не переписывать опубликованную), иначе — исправляющий коммит; `commit_docs: false` дальше |
| Hook ломает `npm run check` | LOW | Игнорируемое место записи, `.prettierignore`/`.gitignore`, тест hook'а |
| Hook блокирует compaction/сессию | MEDIUM | Убрать hook из `settings.json` вручную в обычном терминале (агентом нельзя), перезапустить сессию |
| Двойные планы разошлись | MEDIUM | Выбрать `.planning/ROADMAP.md`, перенести статусы, `docs/plan.md` → указатель, правка `AGENTS.md` с согласованием |
