# Phase 4: Discovery «продление и пени» — Specification

**Created:** 2026-10-26
**Ambiguity score:** 0.17 (gate: ≤ 0.20)
**Requirements:** 8 locked

> Фаза 4 — только Discovery: этот SPEC описывает фичу продления и пеней для следующей вехи
> (LOAN-01). В самой фазе 4 код и тесты не меняются (`git diff --stat main -- src tests` пуст).

## Goal

Выдачу можно продлить не больше 2 раз на 14 дней, за просрочку начисляется пеня 10 ₽ за каждый
начатый день с потолком 300 ₽ на выдачу, а читатель с неоплаченной пеней не получает и не продлевает
книги, пока библиотекарь не отметит пеню оплаченной.

## Background

- `src/domain/loans.ts`: `checkoutBook` выдаёт книгу на `DEFAULT_LOAN_POLICY.loanDays` (14) при лимите
  `loanLimit` (3) и проверяет `NO_FREE_COPIES` раньше `LOAN_LIMIT_REACHED`; `returnBook` отклоняет
  повторный возврат кодом `LOAN_ALREADY_RETURNED`; `isOverdue(loan, now)` — просрочка строго после `dueAt`.
- `src/domain/types.ts`: `Loan { id, bookId, readerId, issuedAt, dueAt, returnedAt }` — нет ни счётчика
  продлений, ни данных о пене; `LoanErrorCode` — три кода.
- `src/server/json-file-repository.ts`: `STORAGE_VERSION = 1`, схема zod требует `version: 1`; есть код
  `UNSUPPORTED_STORAGE_VERSION`. Запись — через временный файл и `rename`.
- `src/server/app.ts`: `POST /api/loans` и `POST /api/loans/:id/return` выполняются через `serial()`,
  отказ домена — `409` с кодом, неизвестная выдача — `404 LOAN_NOT_FOUND`; `GET /api/loans` добавляет `overdue`.
- `src/client/api.ts` переводит коды отказов в русский текст.
- Продления, пеней и блокировки должников нет. Решения `/gsd-explore` —
  `.planning/notes/renewal-and-fines.md`, вопросы — `.planning/research/questions.md`.

## Requirements

1. **Продление**: продление сдвигает `dueAt` на `loanDays` от текущего `dueAt`, не больше 2 раз на выдачу.
   - Current: продления нет, `dueAt` задаётся один раз при выдаче.
   - Target: доменная функция продления возвращает выдачу с `dueAt + 14 д` и счётчиком продлений +1;
     третья попытка — отказ `RENEWAL_LIMIT_REACHED`.
   - Acceptance: выдача с `dueAt = D`, продлённая при `now = D`, получает `dueAt = D + 14 д` (не `now + 14 д`);
     после двух продлений третье отклоняется `RENEWAL_LIMIT_REACHED`, выдача не меняется.

2. **Отказы продления**: продление отклоняется типизированным кодом в фиксированном порядке
   `LOAN_ALREADY_RETURNED` → `LOAN_OVERDUE` → `RENEWAL_LIMIT_REACHED` → `READER_HAS_DEBT`.
   - Current: кодов `LOAN_OVERDUE`, `RENEWAL_LIMIT_REACHED`, `READER_HAS_DEBT` нет.
   - Target: при нескольких нарушениях возвращается первый код по порядку; `LOAN_OVERDUE` — когда `now`
     строго позже `dueAt`; `READER_HAS_DEBT` — по правилу R4 для того же читателя.
   - Acceptance: для каждой соседней пары кодов есть тест с выдачей, нарушающей оба правила, и ожидается
     первый код пары (например, возвращённая и просроченная → `LOAN_ALREADY_RETURNED`).

3. **Расчёт пени**: чистая функция `fineFor(loan, now)` возвращает пеню в целых копейках.
   - Current: пени нет.
   - Target: 1000 коп. за каждый начатый 24-часовой интервал после `dueAt` до `returnedAt`
     (или `now`, если книга не возвращена), не больше 30 000 коп.; без просрочки — 0. Только
     целочисленная арифметика: дней = `ceil(мс_просрочки / DAY_MS)`.
   - Acceptance: при `dueAt = D` — конец в `D` → 0; `D + 1 мс` → 1000; `D + 24 ч` → 1000;
     `D + 24 ч + 1 мс` → 2000; `D + 30 д` → 30 000; `D + 31 д` → 30 000; результат всегда целое число.

4. **Долг блокирует выдачу**: выдача отклоняется `READER_HAS_DEBT`, если у читателя есть выдача с
   `fineFor > 0` без отметки оплаты — в том числе невозвращённая просроченная.
   - Current: `checkoutBook` проверяет только экземпляры и лимит.
   - Target: порядок проверок выдачи — `READER_HAS_DEBT` → `NO_FREE_COPIES` → `LOAN_LIMIT_REACHED`.
   - Acceptance: не блокируют — оплаченная пеня, невозвращённая выдача при `now = dueAt`, возврат
     вовремя; блокирует — невозвращённая выдача при `now = dueAt + 1 мс` и возвращённая с неоплаченной
     пеней; при долге и нехватке экземпляров одновременно — `READER_HAS_DEBT`.

5. **Отметка оплаты**: библиотекарь отмечает пеню по выдаче оплаченной целиком, только после возврата.
   - Current: отметки оплаты нет.
   - Target: до возврата — отказ `FINE_NOT_FINAL`; при `fineFor = 0` — `NO_FINE`; повторно —
     `FINE_ALREADY_PAID`; успешная отметка не меняет сумму `fineFor` и снимает долг.
   - Acceptance: после возврата с пеней 3000 коп. и отметки оплаты `fineFor` по-прежнему 3000,
     а следующая выдача этому читателю проходит; три кода отказа покрыты тестами.

6. **Модель и миграция хранилища**: `Loan` получает счётчик продлений и отметку оплаты; существующий
   файл версии 1 продолжает работать без потерь.
   - Current: `STORAGE_VERSION = 1`, в записях выдач нет новых полей.
   - Target: файл v1 мигрирует в новую версию: у всех выдач 0 продлений и «не оплачено», остальные поля
     без изменений; повторная миграция ничего не меняет; неизвестная версия — `UNSUPPORTED_STORAGE_VERSION`.
   - Acceptance: фикстура v1 (в том числе с пустым `loans`) после миграции даёт те же книги, читателей
     и даты выдач плюс значения по умолчанию; второй прогон даёт идентичный файл; файл с `version: 99`
     отклоняется кодом.

7. **API**: эндпоинты продления и отметки оплаты; пеня в списке выдач.
   - Current: есть только выдача, возврат и список с `overdue`.
   - Target: продление и оплата (рабочие пути `POST /api/loans/:id/renew`, `POST /api/loans/:id/pay-fine`)
     идут через `serial()`; отказ домена — `409` с кодом; неизвестная выдача — `404 LOAN_NOT_FOUND`;
     `GET /api/loans` добавляет `fineKopecks` (целое, на момент `now`) и `finePaid`.
   - Acceptance: supertest проверяет `200`, `409` с каждым кодом и `404`; для невозвращённой выдачи
     `overdue: false` тогда и только тогда, когда `fineKopecks: 0`.

8. **UI**: продление, оплата и пеня в списке выдач.
   - Current: в списке выдач есть только возврат и признак просрочки.
   - Target: «Продлить» — у каждой невозвращённой выдачи, отказ показывается русским текстом по коду;
     «Отметить оплату» — только у возвращённой выдачи с пеней > 0 без оплаты; пеня — «N ₽», без пени — «—».
   - Acceptance: e2e-сценарии «продлить выдачу» и «отметить оплату пени» проходят; 30 000 коп.
     отображается как «300 ₽»; для каждого нового кода отказа в `src/client/api.ts` есть русский текст.

## Boundaries

**In scope (следующая веха, LOAN-01):**
- Доменные правила: продление, `fineFor`, блокировка должника, отметка оплаты, новые коды отказов
- Расширение `Loan` и миграция JSON-хранилища с версии 1
- API: продление, отметка оплаты, `fineKopecks` и `finePaid` в списке выдач
- UI: кнопки «Продлить» и «Отметить оплату», сумма пени, тексты отказов; e2e на продление и оплату

**In scope (эта фаза 4):**
- Только документы Discovery: этот SPEC и CONTEXT из `/gsd-discuss-phase 4`

**Out of scope:**
- Изменения `src/` и `tests/` в фазе 4 — фаза только Discovery (DISC-01)
- Очередь и бронь книг — продление не зависит от ожидающих читателей
- Уведомления читателю о сроке и пене — нет канала доставки
- Касса, частичная оплата, прощение и отмена отметки оплаты — MVP: оплата только целиком
- SQLite, роли и авторизация — хранилище остаётся JSON, «библиотекарь» — любой пользователь UI

## Constraints

- Сумма пени — только целые копейки (`number`, целое), без дробей ни в домене, ни в JSON API.
- Время — параметром `now: Date`, без `new Date()` внутри правил; «начатый день» — 24-часовые интервалы
  от `dueAt`, без часовых поясов, согласованно с `isOverdue`.
- Новые отказы — типизированные коды в `LoanResult`, не строки и не исключения.
- Формат хранилища меняется только с миграцией существующих данных (`AGENTS.md`); запись остаётся
  атомарной (временный файл + `rename`).
- Новые маршруты выполняются через `serial()`, как существующие.
- Без новых npm-зависимостей.

## Acceptance Criteria

- [ ] Продление при `now = dueAt` даёт `dueAt + 14 д`; третье продление — `RENEWAL_LIMIT_REACHED`
- [ ] Продление просроченной (`now = dueAt + 1 мс`) — `LOAN_OVERDUE`
- [ ] Порядок отказов продления `LOAN_ALREADY_RETURNED` → `LOAN_OVERDUE` → `RENEWAL_LIMIT_REACHED` → `READER_HAS_DEBT` закреплён тестом на каждую соседнюю пару
- [ ] `fineFor` даёт 0 / 1000 / 1000 / 2000 / 30 000 / 30 000 в точках `D`, `D+1мс`, `D+24ч`, `D+24ч+1мс`, `D+30д`, `D+31д`
- [ ] `fineFor` всегда возвращает целое число
- [ ] Выдача должнику — `READER_HAS_DEBT`, и этот код важнее `NO_FREE_COPIES` и `LOAN_LIMIT_REACHED`
- [ ] Оплаченная пеня, срок ровно в `dueAt` и возврат вовремя не блокируют выдачу
- [ ] Отметка оплаты: `FINE_NOT_FINAL` до возврата, `NO_FINE` при нулевой пене, `FINE_ALREADY_PAID` повторно; после оплаты сумма не меняется, долг снят
- [ ] Файл v1 (включая пустой `loans`) мигрирует без потерь с 0 продлений и «не оплачено»; повторная миграция идемпотентна; `version: 99` — `UNSUPPORTED_STORAGE_VERSION`
- [ ] Несуществующая выдача при продлении и оплате — `404 LOAN_NOT_FOUND`; отказы домена — `409` с кодом
- [ ] `GET /api/loans` отдаёт `fineKopecks` и `finePaid`; для невозвращённой выдачи `overdue: false` ⇔ `fineKopecks: 0`
- [ ] UI: «Продлить» у невозвращённых, «Отметить оплату» только у возвращённых с неоплаченной пеней, «300 ₽» и «—»; e2e продления и оплаты зелёные
- [ ] `fineFor` для двух выдач разных читателей с одинаковыми датами возвращает одну сумму (P1)
- [ ] В фазе 4: `git diff --stat main -- src tests` пуст
