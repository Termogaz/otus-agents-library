# PRD: понятный интерфейс библиотеки

Первая часть handoff-пакета ДЗ-3. Истории и критерии приёмки — в `user-stories.md`,
визуальные правила — в `DESIGN.md`, задачи — в `ui-plan.md`.

## Проблема

Функции выдачи и возврата работают, но интерфейс не помогает библиотекарю: стилей нет,
просрочка не выделена, ошибка выдачи появляется далеко от формы, а пустой экран не говорит,
с чего начать. Снимки текущего состояния: `docs/screenshots/hw3-before-*.png`.

## Пользователь и цель

Одна роль — **библиотекарь**: ведёт каталог и читателей, выдаёт и принимает книги.
Цель: выдать или принять книгу и сразу понять результат и причину отказа.

Основной сценарий: добавить книгу → добавить читателя → выдать → увидеть срок → принять обратно.

## Функциональные требования

| ID   | Требование                                                                                                                                                                                                   | Проверка |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| FR-1 | Если список книг, читателей или выдач пуст, система показывает вместо него текст о том, что список пуст, и что сделать дальше                                                                                | e2e      |
| FR-2 | При отказе действия система показывает причину (`role="alert"`) внутри раздела, где выполнено действие, и убирает её при следующем успешном действии. Ошибка начальной загрузки показывается вверху страницы | e2e      |
| FR-3 | Пока запрос действия выполняется, его кнопка заблокирована: повторный клик не отправляет второй запрос                                                                                                       | e2e      |
| FR-4 | Статус выдачи показывается текстом и цветом: «На руках», «Просрочена» (выделена цветом ошибки), «Возвращена ДД.ММ.ГГГГ»                                                                                      | e2e      |
| FR-5 | Если действие выполнено, а обновить список не удалось, система не считает это отказом: форма очищается и показано «Сохранено, но список не обновился. Обновите страницу»                                     | e2e      |

## Откуда взято FR-3

Главный риск: повторный клик при медленном ответе. `POST /api/books` создаёт новую запись при каждом
вызове, поэтому двойной клик может дать дубль. По коду риск есть, но ещё не воспроизведён;
воспроизвести его должен e2e этого требования (сначала падающий тест).

## Ограничения

- Домен, API и формат `data/library.json` не меняются; лимит 3 книги и срок 14 дней остаются в `src/domain`.
- Существующие e2e не переписываются. Поэтому остаются: заголовок «Библиотека», текст «API: ok»
  (можно переместить в подвал), имена форм, таблиц и кнопок, текст отказа «Нет свободных экземпляров»
  и его отправка на сервер при выборе книги без экземпляров.
- Тексты интерфейса — на русском.

## Что не входит

- Вход в систему и роли, кроме библиотекаря.
- Продление и пени (Discovery ДЗ-2), поиск и фильтры, редактирование и удаление записей.
- Отдельные страницы и маршрутизация, тёмная тема, optimistic UI (в проекте нет LLM).
- Пометка книг без свободных экземпляров в списке выдачи: полезно, но следующий кандидат, не этот объём.
