# PRD: понятный интерфейс библиотеки

Первая часть handoff-пакета ДЗ-3. Критика этого документа — в `prd-review.md`, истории и критерии приёмки —
в `user-stories.md`, аналоги — в `../research/competitors.md`, визуальные правила — в `DESIGN.md`,
задачи — в `PLAN.md` фазы 6.

## Проблема

Функции выдачи и возврата работают, но интерфейс не помогает библиотекарю: стилей нет,
просрочка не выделена, ошибка выдачи появляется далеко от формы, успех никак не подтверждается, а пустой экран
не говорит, с чего начать. Снимки текущего состояния: `docs/screenshots/hw3-before-*.png`.

## Пользователь и цель

Одна роль — **библиотекарь**: ведёт каталог и читателей, выдаёт и принимает книги.
Цель: выдать или принять книгу и сразу понять результат и причину отказа.

Основной сценарий: добавить книгу → добавить читателя → выдать → увидеть срок → принять обратно.

## Критерии успеха

| ID  | Критерий                                                                                  | Проверка              |
| --- | ----------------------------------------------------------------------------------------- | --------------------- |
| S-1 | Основной сценарий проходит с пустых данных, каждый шаг подтверждён сообщением на экране   | e2e                   |
| S-2 | Причина отказа выдачи видна на экране 1280×800 без прокрутки после нажатия «Выдать»       | e2e: `toBeInViewport` |
| S-3 | Просроченная выдача находится в первых строках таблицы при любом порядке создания записей | e2e                   |

## Функциональные требования

| ID   | Требование                                                                                                                                                                                                                                                                                                                             | Проверка |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| FR-1 | Пока идёт первая загрузка, видно «Загрузка…». После успешной загрузки пустой список заменяется текстом о том, что он пуст, и что сделать дальше. Если загрузка не удалась, текста о пустом списке нет                                                                                                                                  | e2e      |
| FR-2 | При отказе действия система показывает причину (`role="alert"`) в разделе, где выполнено действие, и убирает её при следующем успешном действии. Одновременно на странице не больше одного сообщения об ошибке. Ошибка начальной загрузки показывается вверху страницы                                                                 | e2e      |
| FR-3 | Пока запрос действия выполняется, его кнопка заблокирована: повторный клик не отправляет второй запрос                                                                                                                                                                                                                                 | e2e      |
| FR-4 | Статус выдачи показывается текстом и цветом: «На руках», «Просрочена», «Возвращена ДД.ММ.ГГГГ»; просроченная строка выделена целиком. Порядок строк: просроченные и «На руках» по возрастанию срока, сначала просроченные; затем возвращённые, последние возвраты сверху                                                               | e2e      |
| FR-5 | После успешного действия система показывает его результат (`role="status"`), для выдачи с названием книги, именем читателя и сроком. Формы книги и читателя очищаются, выбор в форме выдачи сохраняется. Если действие выполнено, а список не обновился, это не отказ: показано «Сохранено, но список не обновился. Обновите страницу» | e2e      |
| FR-6 | В форме выдачи под выбранной книгой видно «Свободно: N из M», под выбранным читателем — «На руках: N». Подсказки не блокируют отправку: решение о выдаче принимает сервер                                                                                                                                                              | e2e      |

## Нефункциональные требования

| ID    | Категория       | Требование                                                                                                                   | Проверка                                                        |
| ----- | --------------- | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| NFR-1 | Usability       | На ширине окна от 360 до 1440 px у страницы нет горизонтальной прокрутки; широкие таблицы прокручиваются внутри своего блока | e2e: `scrollWidth` на 360 и 1440 px                             |

## Откуда взято FR-3

Главный риск: повторный клик при медленном ответе. `POST /api/books` создаёт новую запись при каждом
вызове, поэтому двойной клик может дать дубль. По коду риск есть, но ещё не воспроизведён;
воспроизвести его должен e2e этого требования (сначала падающий тест).

## Ограничения

- Домен, API и формат `data/library.json` не меняются; лимит 3 книги и срок 14 дней остаются в `src/domain`.
  Подсказки FR-6 только показывают данные: клиент не решает, можно ли выдать книгу, и не знает значения лимита.
- Существующие e2e не переписываются. Поэтому остаются: заголовок «Библиотека», текст «API: ok»
  (можно переместить в подвал), имена форм, таблиц и кнопок, выбор книги по её точному названию в списке,
  сохранение выбора после выдачи, текст отказа «Нет свободных экземпляров» и его отправка на сервер
  при выборе книги без экземпляров.
- Тексты интерфейса — на русском.

## Допущения

Проверить их на реальном библиотекаре в учебном проекте нельзя; если допущение неверно, требования пересматриваются.

| ID  | Допущение                                      | Если неверно                                    |
| --- | ---------------------------------------------- | ----------------------------------------------- |
| A-1 | Интерфейсом пользуется один библиотекарь       | Нужны вход, роли и обновление данных при гонках |
| A-2 | Записей немного: выпадающие списки справляются | Нужны поиск и постраничный вывод                |
| A-3 | Сканера штрихкодов нет                         | Нужны поле штрихкода, новые данные и миграция   |

## Что не входит

- Вход в систему и роли, кроме библиотекаря.
- Продление и пени (Discovery ДЗ-2), поиск и фильтры, редактирование и удаление записей.
- Маршрутизация и отдельные URL: экраны — это разделы и состояния одной страницы, см. `ux-patterns.md`.
- Тёмная тема, optimistic UI (в проекте нет LLM, а запросы локальны и быстры).
- Вкладки и пометка книг без экземпляров в самом списке: они ломают существующий e2e, см. `../research/competitors.md`.
