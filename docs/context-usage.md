# Контекст и usage: снимки «до» и «после»

Пункт 4 ДЗ-2 (требование CTX-04). Снимки «до» снимаются до любых изменений среды в вехе ДЗ-2,
снимки «после» — тем же сценарием в фазе 3. Сравниваем только снимки одного сценария.

## Сценарий (одинаковый для «до» и «после»)

1. Новая сессия из корня проекта: `cd ~/projects/library && claude` (или `/clear` в открытой сессии).
2. Сразу, без других сообщений: `/context` — скриншот `hw2-context-<before|after>-start.png`.
3. `/usage` — скриншот `hw2-usage-<before|after>.png`.
4. Одна фиксированная команда нагрузки: `/gsd-progress`.
5. `/context` — скриншот `hw2-context-<before|after>-progress.png`.

Скриншоты — в `docs/screenshots/`. Стоимость в `/usage` на подписке — оценка, не реальные расходы.

## Сравнение

- **Старт почти не изменился: 36.8k → 37.4k.** Messages +1.2k — дайджест `SessionStart`; memory files
  −0.7k — `docs/plan.md` (11,7 КБ) заменён на `STATE.md`, хотя `AGENTS.md` вырос; skills +0.2k — `/lib-*`.
  Новая среда почти бесплатна в токенах на старте.
- **Нагрузка та же: messages 58.1k → 56.9k**, всего 95k → 93.2k. Доля окна — 9% → 47%: при окне 1M
  одна команда GSD была незаметна, при 200k видно, что две такие команды подводят к сжатию. Это и
  есть смысл порога: statusline показывает 55% до сжатия, монитор предупредит раньше, чем контекст
  разрастётся.
- **`/usage` между снимками не сравнивается:** проценты — накопленный расход плана на момент снимка
  (сессия 55% → 22%, неделя 19% → 48%), а не цена сценария. Подсказки `/usage` «после» совпадают с
  политикой: «Start fresh when you switch tasks · run /clear» — 64%, субагенты `gsd-planner` — 13%.
- **Политика контекста** — раздел «Контекст» в `AGENTS.md`: когда `/compact`, когда `/clear`, что
  сохранять перед ними.
