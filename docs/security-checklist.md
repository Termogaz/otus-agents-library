# Security-checklist среды агента

Перечень рисков из `.planning/codebase/CONCERNS.md` и запретов ДЗ-1: у каждого пункта есть команда проверки и статус «закрыт», «закрыт частично» или «открыт». «Воспроизводим из git» = «да», если защита живёт в закоммиченных файлах и после `git clone` и `npm ci` работает без ручной настройки. Статус «закрыт» означает: воспроизведённые обходы закрыты и каждый закреплён проходящим тестом (команда `npx vitest run … -t` выбирает хотя бы один тест), а не «обходов не существует». Статус «закрыт частично» означает: перечисленные формы закрыты и закреплены тестами, но повторная верификация фазы 1 воспроизвела обходы того же риска; они названы в строке, а их исправление — первый шаг фазы 2, до подключения памяти. Номера находок: `01-REVIEW.md` — ревью после закрытия пробелов, `01-REVIEW-before-gaps.md` — первое ревью фазы (оба в `.planning/phases/01-…/`). Hooks и deny-шаблоны — эвристика по шаблонам, а не песочница (см. [`about.md`](about.md)): значение, собранное из переменной или подстановки без буквального имени секрета, глобы вида `.e*` и скрипты интерпретаторов, собранные подстановкой, hook не раскрывает; конструкции, которые он не моделирует (канал и heredoc в shell, `eval`, `python -c`), он отклоняет, если в команде виден секрет (fail-closed). Оставшиеся ограничения названы в строках своих рисков. Для открытых пунктов команда показывает текущее состояние, а не успешную защиту; исправления отложены.

Закрыты формы, воспроизведённые верификатором: экранированная кавычка (`echo "\""; cat .env`), clobber-перенаправление и `>&файл`, `$'.env'`, группировка `(cat .env)`, операнды `if=`, `@`, `ref:` (`dd if=.env`, `curl -d @.env`, `git show HEAD:.env`), вложенный shell через канал или heredoc, `eval`, `python -c` со скриптом, где виден секрет (fail-closed: немоделируемая конструкция вместе с упоминанием секрета — отказ). Остаются ограничения эвристики: значение из переменной без буквального токена (`X=.en; cat ${X}v`), скрипт интерпретатора, собранный подстановкой, глоб `.e*` не раскрываются; рекурсивный `grep -r` по корню (и `rg` с `--hidden`, `-u`, `--no-ignore`) даёт `ask`, а не `deny`, и любое `--exclude-dir` снимает запрос (`01-REVIEW.md` WR-02). Закрыты и обходы второго ревью (`01-REVIEW.md` CR-01…CR-03, WR-03, WR-04): комментарий `#` с кавычкой больше не скрывает следующие строки; вложенный shell разбирается по правилам bash (`bash -ce`, `bash -c --`, `ksh`, `fish`, `busybox sh`, `su -c`, `find -exec sh -c`); значение, приклеенное к короткой опции (`curl -d@.env`, `awk -f.env`), и файл `xargs -a` проверяются; фигурные скобки (`cat {.env,x}`, `.e{n,m}v`) раскрываются, `${F:-.env}` отклоняется по fail-closed; pathspec-магия git (`:(top).env`) снимается.
